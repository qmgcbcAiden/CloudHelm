# CloudHelm

CloudHelm 是一个带 AI 助手的桌面 SSH 客户端，面向个人开发者和运维人员。你可以像平常一样连接服务器、使用终端，也可以在右侧用自然语言描述目标，让 AI 调查、提出操作、经过审核后执行，并根据实际结果继续分析和验证。

**不需要先创建任务。** 点击主机打开终端，直接开始对话；后台自动记录操作与审核过程。每个新对话只绑定发起时的一台主机，未连接主机的自由对话不能操作远端。

当前版本为 **0.1.0，开发中**，采用 [AGPL-3.0-only](LICENSE) 许可证。桌面构建目标为 macOS Apple Silicon、macOS Intel 和 Windows x64；自动测试与真实环境验收的区别见[验收状态](docs/STATUS.md)。

## 可以做什么

- **正常使用 SSH**：SSH Agent、私钥或密码认证，主机指纹核对、单跳板机、多个可关闭终端标签和只读 SFTP 文件页。
- **方便管理主机**：主机行的“⋯”打开编辑和安全设置；私钥可通过系统文件选择窗口选择；“测试连接”直接测试未保存的配置。
- **让 AI 协助操作**：Pi SDK 驱动多轮调查、规划、命令执行、结果分析和验证。AI 使用独立真实 SSH PTY，普通终端与 AI 终端互不抢占。
- **查看并接管执行**：审核通过后，完整命令发送到远端并真实回显；在 AI 终端输入即可接管。暂停 AI、停止命令和断开 SSH 是不同操作。
- **选择审核方式**：低风险白名单自动通过，其余操作按主机设置走人工审核、AI 审核或自动执行；已识别的硬禁令在所有档位拦截。
- **配置自己的模型**：双列 Pi 供应商设置，分别填写 API Key、Base URL 和模型，支持测试连接。Jev 审核独立配置；订阅登录尚未开放。
- **读懂结果**：助手回复渲染 Markdown，代码块可复制；错误用友好弹窗说明。完成远端工作后，AI 提交验证证据、访问方式、变更与恢复说明供验收。

例如，在已连接的主机旁输入：

> 帮我检查这个服务的启动方式，把它容器化并启动。先查看现有配置，完成后给我访问地址、验证结果和恢复方法。

这是产品目标场景；真实模型自主完成整套部署的验收尚未完成，不应将本地模拟模型测试当作部署质量保证。

## 开始使用

1. 添加主机，填写地址、端口、账户和认证方式；私钥方式可点击“选择文件”。
2. 点击“测试连接”。如出现指纹确认，通过可信渠道核对后继续；测试不会保存配置，也不会打开终端。
3. 保存主机，点击左侧主机行连接服务器。
4. 在“设置 → API Key”中配置 API Key、地址和模型，测试后保存为默认。
5. 在右侧直接提问或描述要完成的操作；审核和交互请求会在界面中提示。

完整操作说明、模型切换和故障排查见[使用指南](docs/USER_GUIDE.md)。

## 获取与运行

有权限访问仓库 Actions 的用户可在成功的 **CI** 运行中下载构建产物：

| 平台 | Artifact 名称 | 内容 |
| --- | --- | --- |
| macOS Apple Silicon | `CloudHelm-macos-arm64` | DMG |
| macOS Intel | `CloudHelm-macos-x64` | DMG |
| Windows x64 | `CloudHelm-windows-x64` | NSIS 安装 EXE |

产物保留 7 天，当前未签名／公证，不自动发布 GitHub Release。CI 构建成功不等于安装和所有交互流程已完成人工验收。

从源码启动需要 Node.js 24、pnpm 11.9.0，以及本平台原生模块构建工具：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

测试、打包、Windows 构建环境和贡献流程见[开发指南](docs/DEVELOPMENT.md)。

## 安全与数据

所有 Agent 远端变更都经过统一安全入口。第二档优先通过 Vercel Gateway 调用 `typesafe-ai/jev`；未配置 Jev Key 时，由当前主模型发起独立审核。已配置 Jev 但服务故障时转人工，不静默换用模型。模型和 Gateway 的使用费用由对应供应商收取，CloudHelm 当前没有订阅计费功能。

命令审核是对已识别风险的防护，不能保证识别任意脚本的最终效果，也不是远端沙箱。人工手动输入不受 Agent 审核档位约束。模型服务会接收完成对话和审核所需的操作上下文；详情见[安全与数据边界](docs/SECURITY.md)。
